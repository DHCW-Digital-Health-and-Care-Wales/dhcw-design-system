Manual test scenarios
Given a text input. When a user clicks into it and types. Then the text appears in the field as expected.
Must be between 6 and 8 digits long
Given a text input. When a user types past the visible width. Then the field scrolls sensibly and the text doesn't get cut off or hidden.
Given a text input. When a user pastes text into it. Then the pasted text appears correctly — paste is never blocked.
Must be between 6 and 8 digits long
Given the fixed-width variants, e.g. "10 characters" and "20 characters". Then each is roughly wide enough to show that many characters comfortably, not noticeably bigger or smaller.
Given the prefix/suffix variant, e.g. a "£" prefix on a "Cost per item, in pounds" field. Then the label or hint text also explains the expected format in words. And this isn't left to the prefix/suffix alone, since aria-hidden="true" means screen readers never announce it.

Given a numeric-only field, e.g. an account number. When opened on a mobile device. Then the numeric keyboard is shown rather than the full keyboard.
Must be between 6 and 8 digits long
Given a text input. When it receives keyboard focus. Then a clear visible focus indicator is shown around the field.
Given a text input and its label. When the user selects the label. Then focus moves to the associated input field.
Given a screen reader user encounters a text input. When the field is announced. Then the label and any associated hint text are announced with the input.
Must be between 6 and 8 digits long
Given a text input. When browser zoom is increased to 200% or 400%. Then the label, hint text and input remain readable and operable without loss of information.
Given a text input with a long label or hint. When viewed on a small screen or at high zoom levels. Then the text wraps correctly without overlapping the input or other content.
Must be between 6 and 8 digits long, and can be found on the letter we sent you when you registered for this service
Given a text input with a validation error. When the field is displayed. Then the error is clearly communicated using text and visual styling, not colour alone.
