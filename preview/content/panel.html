When to use a panel

Use a panel to:

  • highlight that users have done something successfully
  • display important information when a transaction has been completed

In most cases, the panel component is used on confirmation pages, to tell the user they have successfully completed the transaction.

When not to use a panel

Never use the panel component to highlight important information in body content. Instead consider using:

  • inset text
  • warning callout
  • the pattern to help users decide when and where to get care (care cards)

How to use a panel

A panel is made up of:

  • a heading that confirms what has happened
  • description text, which is optional

How to write panel text

Keep your panel heading text brief. It only needs to summarise what has happened. For example, "Application complete".

Use short words and phrases to make sure highlighted information is easy to read at different screen sizes. Shorter text is less likely to wrap around the panel, which can happen when using the zoom function on mobiles.

If the panel heading needs to be longer, you can reduce the text size by adding the nhsw-panel__title--l class or setting the titleSize: "l" Nunjucks macro option.

You can add more context or details by using additional text under the heading.

Accessibility

Keep text short and concise to ensure it remains fully readable at all zoom levels, including when users apply browser or mobile device zoom. Content must not clip, overlap, truncate or become obscured when users zoom the page or resize text. This supports WCAG 2.2 Success Criterion 1.4.4 Resizing Text, level AA.

Do not rely on colour alone to convey meaning. Use a clear heading so all users can understand the purpose of a panel, regardless of how they perceive colour. This supports WCAG 2.2 Success Criterion 1.4.1 Use of Colour, level A.
