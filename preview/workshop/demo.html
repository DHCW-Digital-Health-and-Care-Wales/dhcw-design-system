1. One shared input foundation

All form controls inherit from the same shared input foundation. Typography, spacing, borders, focus states and error styling are defined once and reused consistently across components.

This reduces ambiguity in implementation. Developers no longer need to decide how inputs should look or behave, because those decisions already exist in the shared component foundation.

Enter your full name.
<input class="nhsw-input nhsw-input--half" type="text">

2. Standardised width behaviour

Width behaviour is standardised through reusable modifiers. Instead of teams creating ad-hoc sizing rules, developers can apply agreed width patterns consistently.

This helps remove inconsistency between services and makes implementation decisions more predictable across teams.

<input class="nhsw-input nhsw-input--width-10" type="text">

3. The same foundation across different inputs

Because components share the same input base, controls such as text inputs, selects and textareas automatically inherit the same typography, spacing and interaction patterns.

This can be different to what you selected before.

This creates consistency by default and reduces the amount of bespoke CSS developers need to write.

<select class="nhsw-select nhsw-select--m">...</select>

4. Shared validation patterns

Validation patterns are shared across components, including error messaging, invalid states and accessible associations.

It is on your National Insurance card, benefit letter, payslip or P60.
Error: Enter a National Insurance number

This ensures users receive consistent feedback patterns regardless of which NHS Wales service they are using.

5. Reducing ambiguity across teams

Information:

A shared style library gives developers clear implementation choices. It captures design decisions once, then makes them reusable across services.

  • Shared foundations create consistent implementation patterns.
  • Typography, spacing and interaction behaviour are centralised.
  • Developers spend less time recreating common UI decisions.
  • Accessibility patterns are built into components by default.
  • Teams can build faster while maintaining consistency across services.
