When to use date input

Use date input when users are likely to know the exact date, for example their date of birth.

When not to use date input

Do not use date input if users are unlikely to know the exact date you're asking about.

How to use date input

Date input consists of 3 fields to let users enter a day, month and year.

Group the fields together in a <fieldset> and use a <legend> to describe them. The legend is usually a question, like "What is your date of birth?".

If you're asking 1 question per page, you can set the contents of the <legend> as the page heading. This is good practice as it means that screen reader users do not hear the same information twice.

Never automatically move users between the day, month and year fields. This can be confusing and interfere with keyboard navigation.

Read more on the GOV.UK Design System about making labels and legends headings.

If you're asking more than 1 question on the page

If you're asking more than 1 question on the page, do not set the contents of the <legend> as the page heading. Read more on the GOV.UK Design System about asking multiple questions on question pages.

Follow GOV.UK guidance on error messages for date inputs.

Use the autocomplete attribute for a date of birth

Use the autocomplete attribute on the date input component when you're asking for a date of birth. This lets browsers autofill the information on a user's behalf if they've entered it previously.

To do this, set the autocomplete attribute on the 3 fields to bday-day, bday-month and bday-year.

Accessibility

When implemented in production, fields should identify their purpose so browsers and assistive technologies can support features such as autofill and reduce user effort. This is to support WCAG 2.2 Success Criterion 1.3.5 Identify Input Purpose, level AA.
