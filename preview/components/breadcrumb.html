When to use breadcrumbs

Use breadcrumbs when users may need to:

  • understand where they are in the wider website or service
  • navigate between related content
  • move back to a higher-level page to explore other options

When not to use breadcrumbs

Do not use breadcrumbs in transactional journeys. They introduce additional navigation options that users do not need while completing a task and may encourage navigation away from the journey before it is complete.

How to use breadcrumbs

If the full breadcrumb trail doesn't fit the screen size, it can wrap onto 2 lines, but do not break a breadcrumb if it doesn't fit the line.

You do not need to show the current page in the breadcrumb because this information is in the H1.

On mobile, we replace the full breadcrumb trail with a "Back to [parent]" link.

We use aria-label="breadcrumb" as a label in the nav element to let people who use screen readers know what it is.

Accessibility

Leave space around breadcrumb links. Avoid placing other interactive elements immediately beside them to reduce the risk of users selecting the wrong thing. This supports WCAG 2.2 Success Criterion 2.5.8: Target Size, level AA.

Make sure all users can see the breadcrumbs. The background colour must have a contrast ratio of at least 4.5:1 with white to meet WCAG 2.2 Success Criterion 1.4.3: Contrast (Minimum), level AA

Source

Learn more about Breadcrumbs in the GOV.UK Design System.

Follow discussions about Breadcrumbs on GOV.UK GitHub to see the latest updates and resolved issues.

This breadcrumbs variant is designed for use on dark backgrounds, where the standard version may not provide enough contrast.

To make sure all users can see the links and arrows, the background colour must have a contrast ratio of at least 4.5:1 against white to meet WCAG 2.2 success criterion 1.4.3 Contrast (minimum), level AA (W3C).

Use the nhsw-breadcrumb--reverse modifier class to show white links and arrows on dark backgrounds.
