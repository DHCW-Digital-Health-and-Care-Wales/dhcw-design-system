When to use a table

Use a table to organise structured data in rows and columns. This can help users scan, compare and find information easily, for example appointment details or vaccination reports.

When to not use a table

Never use the table component to layout content on a page. Instead, use the grid system.

Accessibility

Follow WebAIM's guidance for tables and:

  • give tables captions
  • use the scope attribute to associate the data cells with the appropriate headers
  • let the browser window determine the width of the table whenever possible to reduce horizontal scrolling, this supports WCAG 2.2 Success Criterion 1.4.10 Reflow, level AA

Table captions

Use the <caption> element to describe a table in the same way you would use a heading. A caption helps users find, navigate and understand tables. This supports WCAG 2.2 Success Criterion 1.2.1 Info and Relationships, level A and WCAG 2.2 Success Criterion 2.4.6 Headings and Labels, level AA.

Style table captions to match the visual hierarchy of your page's content. If using Nunjucks, use the captionSize macro option. In HTML add the nhsw-table__caption--l class. You can use sizes s, m, l, or xl.

Table headers

Use table headers (<th>) to tell users what sort of data the rows and columns contain. The combination of row and column headers helps screen reader users identify the data in each cell. This supports WCAG 2.2 Success Criterion 1.2.1 Info and Relationships, level A.

If users need to refer to the first column to understand the context of a cell, for example a name or day of the week, make sure this column's cells are table headers with the scope="row" attribute.

Tables with a lot of data

If possible, you should aim to have less data in your tables. If you have a lot of data, try to organise it into multiple tables or multiple pages.

Do not leave empty cells in a table. The only exception can be the top left cell, where an empty cell may be needed to support the table structure.

If you have missing data, include some short text to explain why it's missing, such as:

  • "No data"
  • "Not applicable"
  • "Not known"

To distinguish the text from other table content, use the nhsw-u-secondary-text-colour modifier class to make it dark grey.
